# 拾念 —— 产品策划案

> 赛道：Spatial Joy 2026 Rokid 全球开发大赛 · AI 赛道（AIUI 智能体）
> 形态：Rokid AI 眼镜（Glasses / Glasses2）+ 手机端
> 提交日期：2026 年 11 月

---

## 〇、摘要

**拾念**是一款戴在眼镜上的记录型智能体。用户在任何双手被占用的时刻，只需说一句“记一下”，想法就会被实时转写、自动结构化，归档为可检索、可执行、可回顾的“想法卡片”。

产品的核心不是“录音”，而是把**一闪而过的念头**变成**随时可用的资产**：能搜到、能变成待办、能在周末被重新看见。

---

## 一、一句话介绍

> 想到就说，说完就能用。

眼镜负责“拾”，AI 负责“念”：拾起每一个不经意的念头，替用户记住、整理、并在合适的时候还给他。

---

## 二、背景与痛点

### 2.1 灵感出现的时刻，往往没有手

- 走路、通勤、做饭、健身、带娃、洗澡后——想法的高发场景，几乎都不是坐在桌前。
- 掏手机记录要解锁、找 App、点输入框，中断成本在十几秒以上，多数人干脆放弃。
- 放弃一次，就等于丢掉一个可能值钱的想法。

### 2.2 语音备忘录只解决了“录”，没解决“用”

- 录完不整理，录音变成“语音垃圾场”，下次再也不会打开。
- 想找上周的想法，只能从头听，无法按主题、人物、项目检索。
- 记录与待办、日程、笔记体系相互割裂，想法无法变成行动。

### 2.3 为什么是眼镜

眼镜是唯一“一直戴在脸上、麦克风常在线、屏幕就在眼前”的设备。它能把记录这个动作压缩到**一句话、两秒钟**，这是手机做不到的。

记录越轻，用户越愿意记；记得越多，数据越有价值；数据越多，回顾越有意义——这是一个正向飞轮。

---

## 三、目标用户与核心场景

**核心用户**：想法高频产出、但缺少整块时间的人——产品经理、创作者、研究者、学生、创业者。

| 典型场景 | 用户状态 | 传统做法 | 拾念做法 |
| --- | --- | --- | --- |
| 通勤 / 散步 | 双手插兜、戴耳机 | 掏手机打字，常放弃 | 说“记一下…”，2 秒结束 |
| 做饭 / 健身 | 手湿、在运动中 | 完全不记录 | 免手语音记录，无需掏手机 |
| 会议 / 访谈 | 不方便打字 | 事后凭记忆补 | 低声记录，自动归入“会议”标签 |
| 睡前 | 不想看屏幕 | 手机备忘录 | 关灯口述，次晨自动整理成卡 |
| 灵感突发 | 正在做别的事 | 记在纸巾、聊天框 | 一句话入卡，自动聚类到主题 |

## 四、产品方案

### 4.1 核心闭环

```
说 → 即时确认 → 自动结构化 → 自动归位 → 回看与输出
```

每一步都尽量不打断用户当前正在做的事。

### 4.2 功能设计

**（1）免手记录**

- 唤醒方式：轻触镜腿，或说“记一下”。
- 说完静音 2 秒自动结束，不需要再说“结束”。
- 眼镜端 1.5 秒内出现“● 已记录 00:12”的反馈，让用户确认已经录上。

**（2）实时结构化**

- 流式转写，说完 8 秒内生成卡片。
- 自动判断类型：灵感 / 待办 / 决策 / 引用 / 素材 / 人脉 / 其他。
- 自动抽取：标题（≤12 字）、摘要（≤50 字）、行动项、人物、项目、时间。

**（3）自动归位**

- 自动补情境标签：时间、地点、通勤 / 会议 / 运动等场景。
- 相近想法自动聚类成主题，例如“选品方向”下自动汇总 7 条碎片。

**（4）回看与输出**

- 眼镜端语音检索：“我上周关于包装的想法”。
- 手机端提供时间轴、标签、全文搜索。
- 一键导出 Markdown、待办清单，或生成可分享的周报卡片。

**（5）主动回顾**

- 每晚 21:30 语音播报今日最重要的 3 条想法（可关闭）。
- 每周日生成“本周想法周报”，包含主题聚类与未完成待办。

### 4.3 交互原则

1. 眼镜端只做三件事：确认在录、确认已存、一句话结果；不做长文本阅读。
2. 复杂操作全部回到手机端，眼镜端保持“说完就走”。
3. 所有结构化结果都能一句话修正，例如“刚才那条改成待办”“删掉最后一句”。

## 五、差异化亮点

1. **从“记录”到“可用”**：同类产品大多停在转写，拾念交付的是带标题、标签和行动项的卡片。
2. **情境即标签**：用户不需要手动分类，时间、地点、场景自动补全，降低整理负担。
3. **记忆回声**：新想法入库时主动提示“你 10 月 12 日提过相似方向”，把孤立碎片连成线索。
4. **零打断**：全程不超过 2 秒操作，符合眼镜“用完即走”的形态，这是手机产品做不到的。
5. **输出即传播**：生成的周报卡片天然适合分享到社群，为作品带来自然增长与使用榜数据。

## 六、技术方案

### 6.1 硬件与系统

- 设备：Rokid Glasses（4 麦阵列、定向拾音、单目显示、49g），代码层面兼容 Glasses2。
- 系统：YodaOS-Sprite；手机端负责缓存、管理与配置。

### 6.2 平台与能力

- AIUI Studio：使用 Skills 技能库完成流式 ASR、意图分类、结构化抽取、向量检索与 TTS。
- 平台内置运行时与一键发布；无需眼镜硬件即可完成设计 → 编码 → 实时调试 → 发布。

### 6.3 技术链路

```
眼镜端 VAD 采集
   ↓ 蓝牙
手机 App（本地缓存 / 上传）
   ↓
AIUI 运行时（流式 ASR → LLM 结构化 → 向量库）
   ↓
眼镜端显示 + 手机端卡片
```

### 6.4 时延预算

| 环节 | 目标时延 | 兜底方案 |
| --- | --- | --- |
| 录音确认反馈 | ≤ 1.5 秒 | 本地提示音与指示灯 |
| 转写完成（30 秒语音） | ≤ 3 秒 | 先显示“处理中”，流式出字 |
| 结构化卡片生成 | ≤ 8 秒 | 先出摘要，标签与行动项后补 |
| 语音检索响应 | ≤ 2 秒 | 缓存最近 200 条做本地检索 |

### 6.5 数据模型

想法卡片字段：`id`、原文、标题、摘要、类型、行动项、人物、项目、时间、地点、场景、关联卡片、音频引用、状态（草稿 / 已确认 / 已完成）。

### 6.6 隐私与合规

- 录音时眼镜指示灯常亮，手机上明示“正在录音”。
- 默认只上传转写文本；原始音频本地保留 24 小时，支持一键删除。
- 会议等涉及他人的场景，首次使用弹窗提示，需征得在场者同意。
- 提供全局暂停录音开关，可随时物理关闭麦克风。

## 九、衡量指标

- 激活：首次记录完成率 ≥ 80%。
- 留存：7 日内有记录的天数 ≥ 3 天。
- 价值：结构化卡片被采纳（未删除、未大幅修改）比例 ≥ 70%。
- 转化：想法转为待办的比例 ≥ 25%。
- 传播：周报卡片分享率 ≥ 10%。

## 十、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 现场网络差 | 转写失败 | 本地缓存 + 断网续传；演示使用本地热点 |
| 嘈杂环境识别率低 | 体验下降 | 定向拾音 + 提示“请靠近说” |
| 结构化不准确 | 用户不信任 | 一句话修正；卡片默认可编辑 |
| 隐私顾虑 | 不敢使用 | 指示灯 + 默认不上传音频 + 一键删除 |
| 旧机型能力差异 | 部分功能受限 | 先用 Glasses 跑通核心链路，Glasses2 做增强 |
